# AILANG World documentation site

The documentation website for AILANG World, built with
[Docusaurus](https://docusaurus.io/) 3.10.2, the same version and theme as the
[AILANG docs site](https://ailang.sunholo.com).

The site builds locally to static files. It does not depend on GitHub Actions.

## Build

Requires Node.js 20 or newer.

```bash
cd website
npm ci
npm run build        # static site in website/build/
```

The build fails on any broken internal link (`onBrokenLinks: 'throw'`).

## Preview locally

```bash
npm run start        # dev server with live reload, http://localhost:3000
npm run serve        # serve the production build from website/build/
```

## Where the site is served

`url` and `baseUrl` come from the environment at build time:

| Variable | Default | Example |
|---|---|---|
| `SITE_URL` | `https://sunholo-data.github.io` | `https://world.example.org` |
| `BASE_URL` | `/` | `/ailang-world/` for a GitHub project page |

```bash
SITE_URL=https://sunholo-data.github.io BASE_URL=/ailang-world/ npm run build
```

## Publish

**Publishing is Mark's call.** Nothing in this repo publishes the site automatically.
Two ways that work without GitHub Actions:

1. **gh-pages branch** (Docusaurus builds, then pushes `build/` to the `gh-pages` branch):

   ```bash
   SITE_URL=https://sunholo-data.github.io BASE_URL=/ailang-world/ \
     GIT_USER=<github-username> USE_SSH=true npm run deploy
   ```

   Then enable GitHub Pages on the `gh-pages` branch in the repository settings.

2. **Any static host**: run `npm run build` with the right `SITE_URL` and `BASE_URL`,
   then copy `website/build/` to the host (a bucket, Firebase Hosting, Netlify, a web
   server, and so on).

## Writing docs

Pages live in `website/docs/`. The sidebar is **autogenerated** from the folders, so you do
not edit `sidebars.js` to add a page.

| Folder | Audience |
|---|---|
| `intro.md` | Everyone: what AILANG World is |
| `concepts/` | Users and operators |
| `getting-started/` | Users and operators |
| `guides/` | Users and operators |
| `security/` | Users and operators |
| `reference/` | Users and operators |
| `agents/` | AI agents |
| `roadmap/` | Everyone: the 1.0 bar and its state |

Conventions:

- **Frontmatter**: every page has `title` and `sidebar_position` (order within its folder).
  Add `description` for search and link previews.
- **Folder landing page**: each folder's `index.md` is the category's landing page (its
  `_category_.json` links to `<folder>/index`). Replace its contents; do not delete it.
- **New folder**: add a `_category_.json` with `label` and `position`.
- **Links between pages**: use relative file links with the extension, for example
  `[roadmap](../roadmap/index.md)`. Docusaurus resolves them and the build checks them.
- **Links to repo files**: use full GitHub URLs, for example
  `https://github.com/sunholo-data/ailang-world/blob/dev/docs/QUICKSTART.md`.
- **Images**: put them in `website/static/img/` and reference them as `/img/<name>`.
- **Code blocks**: tag the language (`bash`, `json`, `go`). AILANG code uses `ailang`
  (highlighted as plain text with an AILANG label).
- Do not invent CLI flags or wire shapes. Copy them from `docs/QUICKSTART.md`, `README.md`
  or the code, whose flags are bound to the CLI by tests.

## Theme

`src/css/custom.css` is copied from the AILANG docs site (`sunholo-data/ailang`,
`docs/src/css/custom.css`) so both sites share the Sunholo palette (primary `#e73c17`,
dark mode `#ff5a3c`) and fonts (Montserrat headings, Inter body, JetBrains Mono code).
World-only rules are at the bottom of that file. The logo, favicon and social card in
`static/img/` are AILANG's, unaltered.
