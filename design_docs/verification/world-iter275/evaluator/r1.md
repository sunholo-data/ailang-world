## Findings

**F1 (BLOCKING). Manifest assembly contents are unasserted.**
- Where: `demo_test.go:1862-1873` (real-stack) and the controls at `:1777-1800`. Nothing in `demoValidateManifest` (`demo_seed.go` ~L770-810) enforces completeness.
- Scenario: the plan's C4 `TestDemoSeedManifestReferences` requires assembling "packet/request/proposal, four evidence refs, invocation/effects...". Removing the packet, request and proposal refs (O6) or the four evidence refs (O10) leaves every test green. The test only checks that whatever refs are present resolve. A manifest with no packet or evidence would pass M4b.
- Fix: in the real-stack test, assert the exact role multiset (goal, two candidates, source, claim, four evidence kinds, packet, request, proposal, and invocation, effect-request and effect-result per run). Add a validator rule that rejects a manifest missing a required role.

**F2 (NON-BLOCKING). "Exactly one packet" is only tested for zero.**
- Where: `demo_seed.go` `len(page.Items) != 1`; the only control is `TestDemoSeedPacketControls/packet-count`, with zero packets.
- Scenario: two packets are accepted (O5 survives) and the `for` loop silently takes the last one. The bug is invisible, because the real stack always has exactly one packet.
- Fix: add a proxy control that serves two items.

**F3 (NON-BLOCKING). Packet anchor binding is unit-tested only on synthetic arguments.**
- Where: `demo_seed.go` workbench GET and `demoValidatePacketAnchor` call site.
- Scenario: forcing `carried=true` (O8) survives, because the real run only has the positive case. A packet carried by the wrong entry would be accepted.
- Fix: a proxy control that returns a workbench body without the anchor sentence.

**F4 (NON-BLOCKING, CI coverage). Fail-closed seed return is pin-gated only.**
- Where: the only seed-level assertion is in the real-stack tests (`:1674`, `:1863`) and `TestDemoSeedApprovalPacket`, all SKIP when the tool pin is unset.
- Scenario: with the tool pin unset (CI), `demoSeedApproval` returning nil survives (O7). The pin-free `s6-fail-closed` test calls `demoS6Incomplete()` directly, so it cannot see this. Everything pin-free that does run covers the validators, scrub, ref resolution, S1 decode, test-index, metadata-index and packet object/decode controls.
- Fix: drive `demoSeedApproval` through a fake daemon in a pin-free test.

**F5 (NON-BLOCKING, hygiene).** `demo_seed.go` imports `host/coordinator` inside the stdlib block (`"strings"` and `"time"` follow it). gofmt accepts it, but it is misplaced.
