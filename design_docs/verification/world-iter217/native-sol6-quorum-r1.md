## Strongest objection

The design requires MCP to reuse `host/projection.allowedDescriptors` for both authorize-time Tools and each fresh Invoke admission (§D108-3/4, §D108-8/9/11), while AC-ADMIT-108 says a genuinely failed registry read must fail closed. The existing helper does not guarantee that property. Its first `GetRegistryHead` can report absent; if the subsequent `transitionreg.NewRequest` fails for **any** reason, `allowedDescriptors` returns `(zero Request, nil, nil)` solely because the earlier check was absent (`host/projection/projection.go:388-400`). `NewRequest` wraps all `ReadSnapshot` failures the same way (`host/transitionreg/bind.go:117-123`); `ReadSnapshot` can fail on head/object reads, missing or corrupt object, and context, as well as true head absence (`host/transitionreg/transitionreg.go:76-120`).

A concrete counterexample is a head published between the precheck and snapshot read, followed by an object-read/store error. The earlier `hasHead=false` masks that genuine failure as an empty allowed set. The existing `TestAgentCard_HeadRaceAbsentThenSucceeds` covers only the successful half of this race (`projection_test.go:642-663`), and `TestAgentCard_HeadReadFailuresAre5xx` injects snapshot failure only when the first head check was present (`projection_test.go:610-640`). Thus the proposed MCP `no-head empty 200` plus generic `genuine errors fail closed` test can pass without exercising this defect. A failed authorization Tools read may be served as an empty `tools/list`; a failed per-item Invoke admission may look like an ordinary not-allowed refusal, obscuring an availability/integrity failure. No unauthorized Dispatch follows, but the stated failure semantics are false.

**Catch:** V7 cites the helper as the reusable admission path but does not verify the absent-precheck/error race; AC-ADMIT has no specific killer for swallowing a snapshot failure after an absent precheck. This is a load-bearing negative-existence/error-classification premise under Gate 2's reject-by-default verification protocol, not a request to redesign MCP batching.

**Proposed fix:** Amend the design to require typed absent-head recognition in the registry reader (or an equivalent verified single-snapshot distinction) before reusing `allowedDescriptors`. Only a confirmed absent head may produce an empty surface; every other snapshot failure propagates as a host error. Add a deterministic two-read fixture: first head check absent, second snapshot read fails with a known injected store error; assert the MCP list and an Invoke admission return the frozen host-error envelope and zero Dispatch. Keep the existing absent→successful-publish control and ordinary absent-head empty 200. Name a mutation that restores the current `if !hasHead { return nil,nil }` catch-all and demonstrate that the new selected test alone kills it. If the fix changes shared A2A behavior, retain its present absent-head and race controls.

## What the r3 closes

Released `mcphttp/handler.go:109-133,136-195` authorizes once per POST and dispatches batch entries sequentially; `methods.go:72-100` invokes once for each reached `tools/call`; a host callback error discards accumulated responses and writes the whole-POST envelope. The doc now states K/J per-item admissions, distinct task IDs, independent receipt/commit outcomes, response-loss retry duplication, and 20-second aggregate context with separate callback and process capacities. `hostcall/runner.go:40-67` confirms that timed-out callbacks retain slots until return. The new AST mount mutation addresses the old vacuous GET-status test: upstream itself returns 405 for GET (`handler.go:72-76`), so changing a method-qualified mux route to a methodless one is only distinguishable by inspecting the registration. Mapping is reversible for admitted names and refuses >64 bytes loudly; schema normalization preserves existing constraints. These points are directionally sound, subject to the blocker above and implementation evidence.
