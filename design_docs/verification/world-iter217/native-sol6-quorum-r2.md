## Full design judgment

I accept the three pending direction choices for this seat. The reversible `_u/_d/_s` name mapping is partial at MCP's 64-byte boundary; refusing the whole dynamic surface on an overlong encoded name avoids aliasing or silent omission. R4 specifies the released seam's bounded HTTP 200/-32603 response and same-mounted-handler recovery after registry repair. Schema normalization retains an existing typed-object byte sequence and protects numeric constraints above 2^53 when adding a missing type. This leaves a visible operator repair path for a valid World ID that cannot be an MCP name.

The aggregate 20-second POST context, 3/10/20-second inner budgets, shared 8-slot MCP Runner and separate 8-child procbound reservation are described without treating either capacity as the other. Released `hostcall.Run` holds its slot until callback return (`runner.go:40-67`), and the design's cooperative teardown, production-constant single/batch legs and late-body residual reflect that fact. The r4 timing fixture now delays only authorize-time Tools, so per-item readmission cannot accidentally consume its 9.8-second setup delay and make the intended invocation timeout test vacuous. The frozen 30-second transport write window is kept; prompt-body envelope delivery is a measured acceptance target, not a universal wall-clock promise.

The non-atomic batch decision matches released `mcphttp`: one ResolveSession/Tools authorization per POST (`handler.go:109-133`), sequential messages (`:159-195`), one Invoke for each reached `tools/call` (`methods.go:72-85`), and whole-POST error on host callback failure. R4 requires fresh per-item registry/capability admission, task IDs, coordinator Dispatch and receipt accounting. It explicitly states that a lost response can hide earlier commits and a retry mints new IDs, so JSON-RPC ids do not imply deduplication. The GET-route AST mutation addresses the historical false-green 405 problem; the real source requires an executable `POST /mcp/` registration, with a same-parse A2A control.

The implementation gate remains substantive: every named mutation must red its selected test then pass on revert, the post-import dependency closure must be measured, and exact final full gates must turn green. At this snapshot the saved sequential base is `verify_ail` rc0 and `verify_go` rc1 on existing `TestDispatchDurableDeadline/uncertain_Commit`; initial concurrent failures differed. R4 records both shapes without a baseline waiver or a product pass claim. No new implementation is certified by this review.
