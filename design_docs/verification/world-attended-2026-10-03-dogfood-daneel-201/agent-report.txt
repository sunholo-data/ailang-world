I swapped in the native `find` and `length` in all nine candidate modules that can be checked here. Every one still passes, and no verify count went down. I left `daneel_sources.ail` alone because it won't even load in this environment.

**Native behaviour, confirmed by running it** (not just from the docs): `find(haystack, needle)` returns the position in characters, not bytes, so it lines up with `substring`. It returns `-1` when there's no match and `0` for an empty needle. That is exactly what the local `indexOf`/`scan` did, including the copies that write `0 - 1` instead of `-1`. The `foldChars`-based `slen` also gives the same answer as native `length` on empty, accented, `—` and emoji strings.

**How I named it:** `daneel_brief.ail` already imported `length as slen`, so I used that same alias everywhere. That avoids the clash with `std/list.length`, and existing `slen(...)` calls didn't need touching. I only removed `foldChars` from an import where nothing else in the file used it.
